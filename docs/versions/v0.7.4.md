# V0.7.4 測試入口移至頁尾

日期：2026-10-23。基準 main `fe656ad5d70653244c4893b375e5edf83d16d187`；使用者明確選擇 A「將按鈕移到頁尾的測試工具區」。

## 使用方式

「① 案件與位置」捲到最下方 →「測試工具」→「載入測試案件」。按鈕在案件檔匯出／開啟、建立新案件及儲存提醒之後；頁首可直接填寫案件資料。

保留原案備份／取代確認、取消保留原案、載入 30 個觀測點與 30 張照片後直接進入「計算與成果」的流程；首次載入需連網。

- 僅調整 HTML 入口位置與區塊標題，並同步版本為 0.7.4。app.js、既有測試斷言、資料檔、store.js、integrity.js、pdf-pages.js、style.css 不變；calc.js 與 sw.js 僅改版本常數。schema、DB_VERSION、CSP 及備份格式不變。

### 驗證與明確限制

- 開工 main／origin/main 乾淨且同步，基準 89／89；完成 **99／99**。新增 10 項：D1 3、D2 1、D3 1、D4 2、D5 2、D6 1。原 app.test.js／pdf-pages.test.js 的完整前綴與斷言保留。
- 375×812 的一般與 demo=1 顯示、空白／已有資料文案、標籤、取消／取代、CSV 警語、總表／整份報告警語、重開正式網址保留 demo 標籤、新案件清除標籤與成果摺疊說明均完成；pageerror=0。刻意測量 fallback 產生 2 則預期 console.warn，未宣稱所有診斷皆零。
- 同份 12 張照片示範案件：總表 2 頁、整份報告 16 頁，合計 18 頁以 PyMuPDF 1.5 倍渲染及逐頁拼貼檢查；保護區塊跨頁 0、超長區塊 0、空白頁 0。設備章節標題、說明與設備照片同頁。
- PDF 保持 scale=2、JPEG quality=0.96；每頁預算 1362×2018、2,748,516 px²，不縮字。診斷用測試照片瘦身與 PDF 輸出畫質是兩個不同設定。
- D4：實際兩份文件無 ≤8% 短末頁。人工控制案例末頁 70px，併入前頁將成為 1050px／頁高 1000px，故依法保留；不能保證所有短頁都併入。選項：維持合法獨立頁，或另議前頁重排；未放寬頁高或自動續做。
- D5：兩種方法頁數及無跨頁結果一致，**座標不是逐像素相同**。總表起點／終點最大差 1.118／1.168px，最終切點相同；報告最大差 0.685／0.735px，2 個切點差 1px。來源為整數 offset 與小數 DOMRect 的差別，不宣稱完全相同。選項：接受此已列明的整數化差異，或後續統一浮點量測；待複審裁定，未自訂允收值。
- 原函式形式參數不變；pageCanvasPlan 回傳新增 optional shortLastPage 診斷欄位。project.demo 未納入既有指紋白名單（integrity.js 依禁改保留）；名稱前綴仍會進入指紋。測試標示不是不可竄改的證明。
- store.js、integrity.js、calc.js、sw.js、vendor 與基準逐位元比對（統一工作樹換行後）不變。schema、DB_VERSION、備份格式、CSP 不變；無 CDN／執行期新套件。
- 實體手機、Safari 與 CSS transform 特殊祖先未實測；本次為隔離 Chromium。D5 使用 CSS zoom 比例，不宣稱支援任意 transform。
- 試跑記錄：新 CSV 測試最初誤以 Blob.text() 檢查 BOM（解碼會略過 BOM），後改核對原始 bytes；VM 陣列原型差異另以 Array.from 正規化後通過。首次瀏覽器腳本讀到上一份 PDF 狀態、報告 DOM 未就緒，補等待預覽種類及可見性；首次總表頁尾跨界 1px 已以有效報告高度修正，原始試跑不算最終通過證據。未刪除或放寬原有斷言。
