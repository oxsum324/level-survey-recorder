# V0.7.6 小修與共同案件識別頭

日期：2026-10-23。基準 main／origin/main `bc73e2a3510c7ffa71ee672bf06ddb583dfadf63`（V0.7.5），開工乾淨同步，Node 基準 99／99。分支 `codex/v0.7.6-header-fields`。本版只交付 PR，未合併／未發布；公開平台仍為 V0.7.5。

## 改動與使用方式

- E1 採派工選項 (a)：短末頁的保護區塊檢查及 hardCuts 改查保留下來的 `previous.start`，僅改這兩行，不更動切頁迴圈、頁高、scale 或畫質。新增診斷測試故意讓人工區塊超過文件末端，區別原錯誤判斷與保留邊界；這是 API 幾何探針，不代表實際文件有超界內容。
- E2 `renderDemoState()` 同時切換 html.demo-case，手機離線狀態樣式改用該 class，正式樣式不再依賴 :has()。真／假與缺少 demo 欄位都測試。
- E3 「① 案件與位置」在案號後加入選填的「戶別／住戶編號」「標的物地址」「鑑定單位／公會」，分別為 householdNo、address、orgName。全棟量測可不填戶別。這是 ADR-0005 的共同識別頭準備，未實作跨工具彙整器。
- 三欄有值才印於總表、報告頁首；空值不印「未填」。原 approxLocation 改標「約略位置（地圖搜尋用）」，保留地圖搜尋用途，不自動覆寫正式地址。
- 新案件預填三個空字串；舊案件 normalize 補空值不觸發 changed；完整案件檔保留選填欄位。schema=1、DB_VERSION=1、level-survey-case.v1 不變。
- calc VERSION、sw CACHE、HTML title／h1 與 README 一般／demo 網址同步 0.7.6。calc.js、sw.js 只有版本常數改動；store.js、vendor、CSP 不變。

## 指紋例外裁定

原派工要求舊案補空字串且指紋不變，但僅加白名單會把新空字串納入指紋。實測 V0.7.0 fixture 原 hash 為 `bfb2bdd0fb104d15c61096f721b6e7d9a824bb7f0349fc1ddafdb253fefed6b6`，若直接把三個空字串加入會變成 `0567d390b6b9ecdfaf8c63c8bdb8549a7bfd1147496e9ddc0fb5867bd71570bb`。

使用者本輪明確允許：指紋程式只略過這三欄的空字串，填值後仍納入。因此 integrity.js 除指定白名單外，另有一處過濾條件變更；只處理這三欄的嚴格空字串，不略過其他既有空值、不改 canonicalize 或 SHA-256。填入、修改任一新欄皆會改變指紋；清空後回到無值的指紋。舊 fixture 補空值、匯入及再次匯出後 hash 仍為上述原值。
